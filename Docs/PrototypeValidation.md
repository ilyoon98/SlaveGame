# 횡스크롤 원정 프로토타입 검증

확인일: 2026-11-06 (Asia/Seoul).

이 문서는 브라우저에서 쓰는 `Prototype/game-core.mjs`를 Node.js에서 직접 실행한 규칙 검증과 실제 브라우저 플레이 결과다. 별도의 시험용 전투 규칙이나 숨겨진 보정은 사용하지 않았다.

## 실제 브라우저 검수

로컬 주소 `http://127.0.0.1:4173/Prototype/`에서 UI 버튼과 역할 선택을 직접 조작했다. 게임 상태를 스크립트로 덮어쓰거나 승리·보상을 주입하지 않았다.

- 첫 초급 원정에서 이동 → 전투 1/2 → 포획 대기 1명/28G → 전투 2/2 → 귀환 → **2명/60G 정산**을 확인했다. 시작 35G에서 95G, 거점 0명에서 2명이 되었다.
- 전투 중 일시정지 전후의 원정 시간이 15.93초로 유지됨을 확인하고, 2배속으로 재개했다.
- 루카를 노동, 에린을 동행에 배치했다. 노동 수익 +0.8G/초와 실제 골드 증가, 동행 1명 전력 증가를 확인했다.
- 40G 훈련 후 대장이 레벨 2, 공격 19, 체력 132가 되었다. 새로고침 후에도 인원·역할·레벨·거점 골드가 복원되었다.
- 최종 14프레임 자산을 다시 로드한 뒤 두 명을 동행에 편성하고 중급 원정을 완료했다. **추가 2명/100G**, 총 거점 인원 4명과 완료 2회를 확인했다.
- 출정 버튼이 화면 아래에 있어 전투를 놓칠 수 있어, 출정 시 전투 영역으로 이동하도록 개선한 뒤 확인했다.
- 콘솔 경고·오류가 수집되지 않았고, 캐릭터와 효과 자산이 정상 로드되었다.
- 검수에 사용한 저장 기록만 초기화하여 사용자에게 시작 골드 35G·인원 0명 상태로 전달했다.

## 애니메이션 검사

- 대기 1장, 걷기 14장, 공격 14장. 128×112px, 공통 피벗 (64,100), 공통 24색.
- `2dimg2motion`의 14프레임 구조 검사에 두 동작 모두 통과했다. 시작과 끝 동일, 키프레임 원본 보존, 발 기준선, 투명 모서리와 프레임 경계를 검사했다.
- 전체 도트 연락표에서 빈손의 어깨갑옷 팔과 검을 든 반대 팔을 확인했다. 브라우저 미리보기에서 반복 재생·일시정지·프레임 진행과 최대 찌르기 자세를 확인했다.
- 걷기 980ms, 공격 770ms이며 게임과 GIF의 총 재생 시간이 같다. 게임 공격 타격은 0.28초다.
- 이 검사는 자연스러움에 대한 사용자 평가나 지면 접촉의 정밀한 속도 일치 검사를 대체하지 않는다.

## 자동 검사

프로젝트 루트에서 실행:

```powershell
node --test Prototype/tests/game-core.test.mjs
```

결과: **15개 통과, 0개 실패**. Node.js v24.18.1, 외부 테스트 패키지 없음.

검증한 플레이 결과:

- 초급 원정이 거점 → 이동 → 전투 → 포획 → 귀환 → 정산을 모두 거친다.
- 공격 준비 중에는 피해가 없으며 타격 시점에 한 번만 피해를 준다.
- 출정 버튼을 중복 입력해도 진행 중인 원정이 바뀌지 않는다.
- 포획 인원과 전리품은 귀환 후 지급되며 같은 결과를 반복 정산할 수 없다.
- 일시정지가 원정 시간, 전투, 노동 수익을 함께 멈춘다.
- 노동 배치로 골드가 증가하고, 원정 편성 인원은 출정 중 노동으로 중복 배치할 수 없다.
- 철수하면 미정산 전리품과 포획 인원을 잃지만 기존 인원은 유지한다.
- 상급 원정에서 실제로 체력이 0이 되어 패배한 뒤, 골드가 0이어도 초급 원정에 재도전할 수 있다.
- 수용 한도를 넘는 인원은 생기지 않으며, 확장 후에는 새 포획 인원을 받을 수 있다.
- 훈련은 골드를 정확히 소비하고 전투력을 높인다. 돈이 부족하거나 원정 중이면 훈련되지 않는다.
- 초급 보상으로 훈련하고 포획 인원 두 명을 편성하면, 기본 전력으로 패배했던 중급 원정을 완료할 수 있다.
- 원정 중 저장 후 새로 시작하면 거점으로 복귀하고 미정산 보상이 복제되지 않는다.
- 저장 스냅샷의 외부 변경은 현재 게임에 영향을 주지 않는다.
- 손상된 저장값은 유효한 시작 상태로 복구한다.
- 2배속은 같은 입력 시간 동안 원정 시계를 두 배 진행한다.

테스트는 공개 메서드(`dispatch`, `tick`, `setRole`, `trainHero`, `retreat`, `getSave` 등)와 정상적인 저장 입력을 사용한다. 진행 중 전투의 체력·피해량·승패를 직접 덮어쓰지 않는다. 테스트의 조건 대기는 최대 180초에서 실패하도록 제한했다.

## 고정 입력 실행 기록

`evaluating-gameplay-balance` 스킬의 실행 조건 명시와 검증 범위 구분을 적용했다. 아래는 정책 탐색이나 인간 플레이를 대체하는 검사가 아니라, 동일한 규칙을 재현하는 **고정 입력 관측**이다.

- 실행 프로필: `precise`, 출발과 사전 편성만 입력. 전투 중 반응·조작 없음.
- 초기 상태: `createDefaultSave()` — 영웅 레벨 1, 골드 35, 포획 인원 0.
- 시간 입력: 1/120초, 1배속, 최대 실행 시간 120초.
- 난수 시드: 없음. 현재 원정 규칙과 적 구성이 결정적이며 RNG를 사용하지 않는다.
- 숨겨진 정보 사용, 최적 정책 탐색, 검색 예산: 없음.
- 아래 소요 시간은 게임 시뮬레이션 시간이며 컴퓨터의 실제 실행 대기 시간이 아니다.

| 시작 조건 | 목적지 | 결과 | 시간 | 정산 골드 | 포획 인원 | 귀환 시 체력 |
| --- | --- | --- | ---: | ---: | ---: | ---: |
| 초기 전력 | 초급 | 성공 | 25.225초 | 60 | 2 | 82 / 110 |
| 초기 전력 | 중급 | 패배 | 27.383초 | 0 | 0 | 0 / 110 |
| 초기 전력 | 상급 | 패배 | 16.150초 | 0 | 0 | 0 / 110 |
| 초급 1회 완료 → 영웅 1회 훈련 → 포획 인원 2명 편성 | 중급 | 성공 | 25.225초 | 100 | 2 | 97 / 168 |

초급 첫 원정의 관측 내역:

- 이동 9.750초, 전투 8.150초, 포획 연출 3.317초, 귀환 4.008초.
- 영웅 타격 9회, 적 타격 5회.
- 각 적 격파 시 임시 포획되며 정산 전까지 거점 인원에 추가되지 않는다.

확인할 수 있는 결론은 **최소 성장 순환이 실제 규칙으로 연결되어 있고, 패배해도 재시작할 수 있으며, 보상이 중복 지급되지 않는다**는 것이다. 목적지별 난이도가 적절한지, 노동과 원정의 수익이 균형 잡혔는지, 플레이가 재미있는지는 아직 판정하지 않았다.

## 검증 범위 밖

- 이 자동 검사는 Canvas의 실제 그림, 스프라이트 접지, 걷기 루프, 검과 손의 연결을 검사하지 않는다.
- 브라우저 버튼·자산·실제 플레이 화면은 위 범위에서 별도로 확인했다. 모바일 화면과 여러 브라우저의 호환성은 아직 검증하지 않았다.
- 인간의 반응·주의·입력 제약을 반영한 `human-limited` 비교를 하지 않았다. 따라서 소요 시간을 근거로 체감 난이도나 플레이 템포의 적절성을 주장하지 않는다.
- 단조로운 배치와 다양한 배치의 정책 비교, 장기 경제·성장 정체·무한 파밍 검사는 아직 수행하지 않았다. `exploratory_ratio`도 계산하지 않았다.
- 실제 사용자 플레이 기록이 생기면 같은 규칙 버전을 기준으로 추가 측정한다.
