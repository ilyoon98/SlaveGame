# 거점 육성 경영 프로토타입 검증

확인일: 2026-11-06 (Asia/Seoul).

브라우저가 사용하는 `Prototype/management-core.mjs`를 Node.js에서 직접 실행하고 실제 브라우저 UI도 조작했다. 별도 시험용 규칙, 강제 승리나 보상 주입은 사용하지 않았다. 자동 규칙 검증과 화면·조작 검수를 구분한다.

## 브라우저 조작 검수

`http://127.0.0.1:4173/Prototype/`에서 버튼과 확인창을 직접 조작했다. 게임 내부 상태를 스크립트로 변경하지 않았으며, DOM에 표시된 값과 화면을 읽어 결과를 확인했다.

- 기본 120G·2명에서 루카 무예 교육과 고블린 일행 파견을 함께 시작했다. 골드는 112G, 교육 자리는 1/1이 되었으며 루카는 거점에 남았다.
- 에린을 선택했을 때 교육 자리 부족 사유와 비활성 버튼이 표시되었다. 다른 시설인 공연장에는 배치할 수 있었다.
- 일시정지와 2배속을 조작했다. 교육·공연·원정이 함께 진행되어 루카 무예 3→7, 공연 수입 22G, 신규 로웬 1명을 확인했다. 이때 골드는 134G, 인원은 3명이었다.
- 루카 경기와 에린 예능 교육을 시작한 뒤 진행률 3%에서 멈추고 새로고침했다. 골드 126G와 진행 일정이 복원되었으며 비용이 다시 청구되지 않았다. 완료 후 에린 예능 3→7, 경기 상금 32G, 골드 158G, 교육 완료 2회·경기 1회·공연 1회를 확인했다.
- 루카 판매 확인창에 대상과 가격 58G가 표시되었다. 확정 후 골드 216G, 인원 2명, 판매 1회가 되었으며 루카가 명단에서 빠졌다.
- 교육실 90G·숙소 70G를 구매해 골드 56G, 교육 자리 2개, 숙소 정원 8명이 되었다. 에린 휴식 후 컨디션 72→100을 확인했다.
- 새로고침 후 숙련·실적·골드·시설과 인원이 유지되었다. 초상화 피부색이 변하는 필터와 잘못된 초기 기록 문구를 수정하고 다시 확인했다.
- 배경의 다섯 시설과 공연 무대 접지를 실제 화면에서 확인했다. 공연장 진입 시 공중을 가로지르지 않도록 무대 배치를 분리했다.
- 검사한 데스크톱에서 문서 너비와 표시 너비가 모두 1265px로 같아 가로 넘침이 없었다. 수집된 브라우저 콘솔 경고·오류는 없었다.
- 사용자에게 넘기기 전, 검수용 기록만 초기화해 120G·2명·교육 자리 1개의 시작 상태로 돌렸다.

화면 증거: [거점과 육성 화면](../Art/Previews/management-prototype.jpg), [판매 확인창](../Art/Previews/management-sale.jpg). 배경 데이터·크롭·발 위치는 [generate2dmap 검증](MapValidation.md)에 별도로 기록한다.

## 자동 검사

프로젝트 루트에서 실행:

```powershell
node --test Prototype/tests/management-core.test.mjs
```

결과: **20개 통과, 0개 실패**. Node.js v24.18.1, 외부 테스트 패키지 없음.

확인한 동작:

- 고블린 주인공 일행 3명과 인간 육성 인원은 서로 다른 명단과 ID를 사용한다. 원정 일행을 교육하거나 판매할 수 없다.
- 교육 자격 조회는 상태를 바꾸지 않는다. 교육 시작 시 비용·컨디션이 차감되고, 시간이 끝나야 숙련도와 판매 가치가 상승한다.
- 동일 인원 중복 일정과 교육실 정원 초과를 추가 비용 없이 거부한다. 서로 다른 시설은 동시에 사용할 수 있다.
- 일정 취소 후 비용·컨디션은 환불하지 않으며, 이후 완료 보상이 발생하지 않는다.
- 낮은 컨디션과 부족한 숙련도는 활동을 막는다. 무료 휴식으로 회복할 수 있고 컨디션은 100을 넘지 않는다.
- 무예 교육 후 경기, 예능 교육 후 공연이 실제 골드·실적을 한 번 지급한다. 경기장과 공연장에는 각각 한 명만 배치할 수 있다.
- 활동 중 판매와 오래된 가격으로 확정한 판매를 거부한다. 판매 시 인원이 명단에서 빠지고 골드가 증가하며 재판매되지 않는다.
- 원정은 고블린 일행만 수행하고 거점 교육과 동시에 진행된다. 귀환은 새 인원 한 명만 추가하며 중복 파견·정산이 없다.
- 숙소가 가득 차면 출정하지 않는다. 판매로 한 자리를 확보한 뒤 원정을 완료해도 정원을 넘지 않는다.
- 교육실·숙소 확장이 실제 동시 교육 수와 인원 수용 한도를 바꾼다. 최대 확장과 자금 부족 시 비용이 차감되지 않는다.
- 골드가 0이어도 무료 경기·공연, 휴식, 원정과 판매로 자금을 마련할 수 있어 회복 경로가 있다.
- 진행 중 교육과 원정을 저장·복원해도 재청구 없이 남은 시간부터 이어진다. 로딩 자체에는 오프라인 보상이 없고 완료 후 다시 로드해도 보상이 중복되지 않는다.
- 저장 객체와 현재 게임 상태는 분리된다. 외부에서 저장 사본을 수정해도 현재 상태가 변하지 않는다.
- 일시정지는 교육과 원정을 모두 멈춘다. 2배속은 같은 입력 시간에 두 배 진행한다.
- 잘못된 행동·시간 입력은 상태를 손상하지 않는다. 손상 저장의 중복 인원·범위 밖 수치·알 수 없는 일정·정원 초과 일정·변조된 원정 명단과 기간을 정리한다.
- 이미 완료된 것으로 조작한 일정이나 원정은 보상 청구로 취급하지 않는다.

테스트는 공개 API와 저장 입력을 사용한다. 컨디션·돈 부족, 손상 저장 같은 경계 사례는 명시적인 시작 저장값으로 구성한다. 진행 중인 일정에 완료 결과를 강제로 쓰지 않는다. 조건 대기는 최대 90초의 시뮬레이션 시간에서 실패한다.

기존 `game-core.test.mjs`는 이전 원정 프로토타입의 검사로 보존했다. 새 경영 기능의 통과 수에 기존 테스트를 포함하지 않았다.

## 고정 입력 실행 기록

초기 저장은 기본값(120G, 인간 2명, 숙소 6명, 교육 자리 1개)을 사용했다. 1배속, 시간 입력 0.05초, 난수와 정책 탐색 없이 아래 순서대로 API를 호출했다. 시간은 컴퓨터의 실제 대기 시간이 아닌 게임 시뮬레이션 시간이다.

1. 루카 무예 교육과 고블린 원정을 함께 시작한다.
2. 10초에 에린 예능 교육과 루카 경기를 함께 시작한다.
3. 20초에 에린 공연을 시작한다.
4. 경기·공연 완료 후 루카를 현재 가격으로 판매한다.
5. 교육실과 숙소를 한 번씩 확장하고 에린을 쉬게 한다.

| 관측 시점 | 보유 골드 | 인원 | 관측 결과 |
| --- | ---: | ---: | --- |
| 시작 | 120G | 2명 | 루카 무예 3, 에린 예능 3, 루카 판매 예상가 32G |
| 10초 | 112G | 2명 | 루카 무예 7, 판매 예상가 52G, 교육 1회 완료 |
| 20초 | 104G | 3명 | 에린 예능 7, 교육 2회 완료, 원정 귀환으로 인원 1명 확보 |
| 22초 | 136G | 3명 | 루카 경기 상금 32G, 경기 실적 1회, 판매 예상가 58G |
| 32초 | 166G | 3명 | 에린 공연 수입 30G, 공연 실적 1회 |
| 판매 직후 | 224G | 2명 | 루카 판매 58G, 명단에서 제거 |
| 시설 투자 직후 | 64G | 2명 | 교육실 90G·숙소 70G 소비, 교육 자리 2개·숙소 8명 |
| 40초 | 64G | 2명 | 에린 컨디션 72 → 100 회복 |

이 기록으로 **교육 → 활동 수익·실적 → 판매 → 시설 투자** 순환과 거점 운영 중 별도 원정을 확인했다. 학습 전략이 최적인지, 판매와 보유의 수익 균형이 적절한지, 장기간 재미가 유지되는지는 판정하지 않았다.

## 검증 범위와 남은 한계

- 초급 경기와 공연은 자격을 충족하면 시간이 끝날 때 정해진 수식을 정산하는 최소 구현이다. 상대별 전투 승패·실패 확률·토너먼트·팀 공연은 아직 없다.
- 판매가는 교육과 실적에 기반한 고정 수식이며 구매자별 수요나 가격 변동은 없다.
- 장기 경제, 원정 후 즉시 판매와 교육·보유 전략의 수익 비교, 인원 수가 많을 때의 관리 피로는 아직 검증하지 않았다.
- 자동 검사는 그림과 조작감을 판정하지 않는다. 데스크톱 배경·시설·버튼·저장·콘솔은 위 브라우저 범위에서 확인했다. 모바일 기기와 여러 브라우저의 호환성·성능은 아직 검증하지 않았다.
- 사용자 플레이나 실제 반응 시간을 측정하지 않았으므로 관측한 초 단위 수치를 체감 템포나 재미의 증거로 사용하지 않는다.
